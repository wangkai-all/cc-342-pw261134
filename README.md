# 本地虚构业务门户 + 真实浏览器采集台

这是一个**完全虚构、仅本机运行**的演示系统：一个把结算报表放在嵌入式子页面里的业务门户，
外加一个用真实 Chromium 操作门户、接收下载并把结果入库的采集台。

没有任何真实公司、账号或数据；演示账号只存在于本地代码里，登录校验是真实执行的，
采集台也只会像人一样填写门户的登录/续期表单，不注入 Cookie、不调用内部接口跳过验证。

## 快速开始

```bash
npm install
npm start
```

- 门户：<http://127.0.0.1:4310/portal>

## 业务结构

- **组织在外层页面选择**：`/portal?org=...`，切换组织会整页重新加载报表子页面。
- **账期在子页面内选择**：报表 iframe 里自带账期下拉框和“生成并下载 CSV”按钮。
- **登录续期替换整个子页面**：会话到期后，报表 iframe 会变成续期页；续期成功后面板回到
  *默认组织 + 默认账期*，不会记得之前选过什么。

## 采集台怎么工作

1. 在采集台选组织、账期（可选：会话续期演练、关闭浏览器演练）后发起采集。
   业务条件写进数据库，成为唯一事实来源。
2. 采集器启动真实 Chromium（持久化 profile），通过门户登录/续期表单进入已登录状态。
3. 按库里的 `org`、`period` **重新操作页面**：外层切组织 → 子页面切账期，每一步都重新解析
   当前 frame 并核对页面显示的条件；任何旧句柄都不会复用。
4. 点击生成前，先用本轮唯一的对账码（`run_key`）查询门户是否已有生成记录：
   - 没有 → 点击生成；
   - 已有 → 只下载既有文件，**不重复生成**。
5. 页面跳走、会话到期或下载超时时，先核实生成记录再决定是否重试。
6. 收到文件后核对文件名（组织/账期）与 CSV 每一行（组织、账期、类型、对账码），
   通过才入库，页面上显示“与条件一致”和 SHA-256。

## 保存与恢复的边界

| 内容 | 存放位置 | 恢复时如何使用 |
| --- | --- | --- |
| 组织、账期、报表类型 | SQLite `conditions` / `runs` | 唯一事实来源；每次操作后与页面核对 |
| 幂等键（对账码） | SQLite `runs.run_key` | 生成前后查询生成记录，避免重复生成 |
| 阶段、尝试次数、事件 | SQLite `runs`、`run_events` | 决定从哪一步继续，并留下可审计轨迹 |
| iframe / Frame / Locator / 下拉框值 / 页面 URL | **不保存** | 恢复时重新启动浏览器、重新解析页面、重新选择条件 |
| 登录 Cookie | 浏览器 profile 目录 | 可能随时过期；过期就走门户续期表单 |

对应地，系统中不会出现“缓存一个旧控件继续点”或“续期后默认回到第一个组织”的行为：
恢复流程只从数据库读组织与账期，然后重新操作页面；页面若回到默认组织，会立刻被改回库里的值。

## 演练场景

采集台发起采集时可以选择：

- **操作途中到期**：应用条件后，通过门户真实的“模拟会话到期”按钮撤销当前授权；
  下一次生成会落在续期页，采集器用表单续期 → 重新选择组织与账期 → 再生成。
- **生成已生效但返回前到期**：门户生成了报表、写入了记录，但在返回文件前撤销会话；
  采集器看到续期页后先查生成记录，查到就直接下载，不会重复生成。
- **应用条件前 / 后关闭浏览器**：真实关闭并重启 Chromium；之前的 Page/Frame/Locator 全部失效，
  恢复时只依据数据库条件重新驱动页面。

也可以在采集台的“浏览器 profile”面板手动关闭浏览器，然后对任意已结束的运行点击
“从库中条件恢复”，验证文件来自既有生成记录而不是第二次生成。

## 数据与留存

- 数据库：`data/collector.sqlite`
- 下载留档：`data/downloads/<run-id>/...`
- 浏览器 profile：`data/profiles/default/`

`data/` 与 `.runtime/` 已在 `.gitignore` 中忽略。

## 测试

```bash
npm test                    # 全部：5 个单元测试 + 12 个真实浏览器端到端测试
npm run test:portal         # 只跑单元测试
npm run test:collector      # 只跑端到端测试
```

端到端测试会真实启动服务与 Chromium，覆盖：按条件采集、不同组织连续采集、
操作途中续期、生成后到期、应用条件前后关闭浏览器、关闭全部浏览器后从库中恢复、
按生成记录地址回退下载，以及从采集台网页发起采集和查看运行详情。

## 运行环境

项目在无图形界面、缺少系统 Chromium 依赖的容器里开发，因此仓库外附带了一份
`.runtime/`（Chromium 与最小动态库集合）。`src/runtime.js` 只在相关环境变量未设置时
引用它；在普通机器上直接 `npx playwright install chromium` 后运行即可，无需 `.runtime/`。

可配置的环境变量（参考 `.env.example`；本项目不会自动加载 `.env`，请用 shell 导出）：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `HOST` / `PORT` | `127.0.0.1` / `4310` | 监听地址 |
| `DATA_DIR` | `data` | 数据库、下载留档、浏览器 profile |
| `COLLECTOR_HEADED` | 未设置 | 设为 `1` 显示真实浏览器窗口 |
| `PORTAL_USERNAME` / `PORTAL_PASSWORD` | 演示账号 | 采集器用于门户登录 |
| `NAVIGATION_TIMEOUT_MS` | `20000` | 页面导航超时 |
